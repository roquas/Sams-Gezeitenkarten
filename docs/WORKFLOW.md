# Arbeitsmodus und Releases

**Verbindliche Quelle:** Repository, Issues und später Pull Requests statt alleiniger Chat-Erinnerung.

**Backlog-Ablauf (Vorschlag):** Idee → Ausgewählt → Spezifiziert → In Arbeit → Review/Test → Erledigt. Ein Issue im Backlog ist ausdrücklich **keine** Zusage für den nächsten Build.

**Änderungsregel:** Betroffene Anforderungen und Tests identifizieren; nur freigegebene Änderungen implementieren; Tests ergänzen und Regression prüfen; Abweichungen offen berichten. Architekturänderungen vorher besprechen.

**Versionen:** 3.6 = letzter gespielter Prototyp, kein Produktionsrelease. Baseline 0.1 = Dokumentationsstand, **keine neue Spielversion**. Künftige Releases nach definiertem Test-Gate.

**Privatsphäre:** Privates Repository ohne Lizenz. Veröffentlichung und Grafiklizenzen gesondert entscheiden.
